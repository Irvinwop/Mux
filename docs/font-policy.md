# Closed Nix font environment

The Nix launcher uses the self-contained Fontconfig configuration generated by
`nix/font-policy.nix`. The policy identifier is `mux-fonts-v1`; the actual font
versions and bytes are determined by `flake.lock`. This is an installed-font
environment policy, not a claim of browser fingerprint resistance.

## Why not makeFontsConf

At the pinned nixpkgs revision, `makeFontsConf` defaults include host/system font
directories and `/etc/fonts/conf.d`. Its transformation also emits an XDG font
directory unconditionally, so empty `impureFontDirectories` and `includes` alone
would not close the font environment.

The replacement starts with `<reset-dirs/>` and lists only absolute
`/nix/store/.../share/fonts` paths from declared font packages. It has no
`<include>` elements, relative font directories, home-directory font sources, or
XDG font sources. The launcher's absolute `FONTCONFIG_FILE` therefore does not
load user `fonts.conf`, `conf.d`, or system Fontconfig defaults. The XDG cache
entry is writable metadata storage, not a directory to search for font files.
The existing launcher exports are unchanged.

The behavior of these elements is documented in the
[Fontconfig user manual](https://fontconfig.pages.freedesktop.org/fontconfig/fontconfig-user.html).
The nixpkgs behavior is visible in the pinned
[configuration helper](https://github.com/NixOS/nixpkgs/blob/1559d3daa3ecc813a650b79375ea61b6741b8746/pkgs/development/libraries/fontconfig/make-fonts-conf.nix)
and its
[XML transformation](https://github.com/NixOS/nixpkgs/blob/1559d3daa3ecc813a650b79375ea61b6741b8746/pkgs/development/libraries/fontconfig/make-fonts-conf.xsl).

## Declared font set

| Pinned nixpkgs package | Purpose |
| --- | --- |
| `roboto` | Existing sans-serif appearance and Arial/Google Sans substitution |
| `dejavu_fonts` | Existing serif, sans, and monospace families |
| `noto-fonts` | Additional scripts and sans/serif fallback |
| `noto-fonts-cjk-sans` | Chinese, Japanese, and Korean glyph coverage |
| `noto-fonts-color-emoji` | Color emoji |
| `stix-two` | Mathematical typesetting and scientific glyphs |

The primary mappings remain Roboto for `sans-serif`, `system-ui`, `Arial`, and
`Google Sans`; DejaVu Serif for `serif`; and DejaVu Sans Mono for `monospace`.
Explicit `math` and `emoji` aliases select STIX Two Math and Noto Color Emoji.
Fontconfig can select script fallbacks from the declared packages. No single
CJK language variant is forcibly selected for every document language.

This increases the font closure size and intentionally removes locally installed
fonts, custom user aliases, and system Fontconfig tuning. Sites that depend on
unbundled local fonts will fall back; downloaded web fonts remain a separate
mechanism and are not blocked by this policy. Package, alias, and lock updates
can change metrics and the observable font set. A future browser privacy/profile
descriptor must account for the font-set revision and locked contents rather
than treating the policy label alone as a stable fingerprint cohort.

## Standalone Nix check

Run on the corresponding Linux builder:

```sh
nix build .#checks.x86_64-linux.font-policy
nix build .#checks.aarch64-linux.font-policy
```

The check does not require WPE, a display server, or a browser build. It copies
a pinned Inconsolata font, which is not in the allowed package set, into isolated
XDG, legacy home, Nix profile, and host-like fixture directories. It also plants
foreign-font configurations in common user and `FONTCONFIG_PATH` locations.
An explicit permissive positive control must discover each copied font first.
The actual policy must then expose a nonempty font set whose canonical file
paths exactly match files independently enumerated by following symlinks under
the declared font roots. Every enumerated target must be in the Nix store, but
store membership alone never authorizes a font. This permits declared package
links, such as DejaVu's minimal-font dependency, without admitting unrelated
store or host fonts. Traversal and resolution failures are fatal, and the
planted foreign family must remain absent. Alias checks and representative
script/math/emoji codepoints catch an accidentally empty or obviously
incomplete replacement.

The output retains the configuration, policy identifier, canonical allowed
roots, sorted reachable canonical files (`allowed-font-files.txt`), sorted
source-to-target mappings (`declared-font-source-targets.tsv`), effective
file/family inventories, alias matches, glyph sample matches, and normalized
positive-control paths. These are Fontconfig-level checks only.
The host-like directory is a private fixture, not a modification to `/usr` or
the real user's home. The font policy is not a filesystem security boundary
against a process or user that can replace the launcher or its environment.

## Required browser measurements

Before claiming browser-level font isolation, measure the launched WPE build
with the same distinctive font installed outside the declared packages:

1. Exercise CSS `local()` font loading, computed fallbacks, and text metrics in
   windows and frames, including after navigation, popups, and process swaps.
2. Exercise canvas text/readback and available worker/OffscreenCanvas font paths
   in dedicated, shared, and service workers where those APIs are supported.
3. Confirm the effective font environment reaches the Web/GPU processes and
   compare equivalent probes on two hosts with different installed fonts.
4. Check script shaping, mathematical layout, emoji rendering, and downloaded
   web fonts for compatibility, not just font metadata coverage.

`fc-list` passing cannot establish those behaviors, identical rasterization
across machines, canvas noise, or Tor Browser-equivalent anonymity.
